For most workflows you will never touch an ABI directly — the SDK's high-level classes (`TokenFactory`, `AssetRegistry`, `EscrowManager`, etc.) handle contract interaction on your behalf. However, there are scenarios where you need raw ABI access: building a custom UI that reads contract state directly, integrating with a wallet library that expects ABI fragments, writing scripts that call contract functions not yet surfaced by the SDK, or constructing multicall batches. In all these cases, `@ankarachain/sdk` exports every contract ABI as a named constant so you don't have to maintain a separate ABI JSON file.

```typescript
import {
  FARMLAND_TOKEN_ABI,
  ESCROW_FACTORY_ABI,
  MILESTONE_ESCROW_ABI,
} from "@ankarachain/sdk";
```

All ABIs are typed `as const` — TypeScript can infer the exact function and event shapes.

## Escrow ABIs

### `ESCROW_FACTORY_ABI`

Deploys `MilestoneEscrow` contracts. Exposes `deployEscrow`, `setImplementation`, `setStablecoinAccepted`, `acceptedStablecoins`, `implementation`, `totalDeployedEscrows`, `getDeployerEscrows`, `deploymentFee`, and `EscrowDeployed`.

### `MILESTONE_ESCROW_ABI`

The per-deal escrow contract. Exposes the full milestone lifecycle:

| Function | Description |
|---|---|
| `fund(milestoneId)` | Payer funds a specific milestone tranche |
| `markDelivered(milestoneId)` | Payee marks a milestone as delivered |
| `approveMilestone(milestoneId)` | Payer releases funds to payee |
| `raiseDispute(milestoneId)` | Payer opens a dispute |
| `resolveDispute(milestoneId, releaseToPayee)` | Arbiter resolves the dispute |
| `claimTimelockRelease(milestoneId)` | Payee claims after timelock expires |
| `voteCancel()` | Either party votes to cancel the deal |
| `setArbiter(newArbiter)` | Admin reassigns the arbiter |
| `getMilestone(milestoneId)` | Read milestone struct |
| `remainingBalance()` | Unallocated balance in the contract |

## Ramp Settlement ABIs

### `RAMP_SETTLEMENT_FACTORY_ABI`

Factory for on-chain ramp settlement contracts. Exposes `deployRampSettlement`, `setImplementation`, `implementation`, `totalDeployedRampSettlements`, `getDeployerRampSettlements`, `deploymentFee`, and `RampSettlementDeployed`.

### `RAMP_SETTLEMENT_ABI`

Per-deployment ramp settlement contract. Exposes `treasury`, `initiateOffRamp`, `confirmOffRampSettlement`, `refundOffRamp`, `recordOnRampSettlement`, `getOffRamp`, `getOnRamp`, `setTreasury`, `pause/unpause`, and all four settlement events.

## Usage example

```typescript
import { Contract, JsonRpcProvider } from "ethers";
import { FARMLAND_TOKEN_ABI, getNetwork } from "@ankarachain/sdk";

const network = getNetwork("polygon");
const provider = new JsonRpcProvider(network.rpcUrl);

const token = new Contract(
  "0xYourDeployedFarmlandTokenAddress",
  FARMLAND_TOKEN_ABI,
  provider,
);

const metadata = await token.getMetadata();
console.log(metadata.location);     // e.g. "Kaduna, Nigeria"
console.log(metadata.areaSqMeters); // bigint
console.log(metadata.valuationUSD); // bigint (in wei)

const status = await token.status();
console.log(status); // 0 = DRAFT, 1 = ACTIVE, etc.
```

<Note>
  For most use cases, use the high-level SDK classes instead of raw ABIs. `AssetRegistry` wraps `getMetadata()` and `setStatus()` with a clean TypeScript API. Direct ABI usage is recommended only for advanced integrations or when calling contract functions that are not yet surfaced by the SDK classes.
</Note>
