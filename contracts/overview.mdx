Ankara Chain ships two parallel contract suites — Solidity contracts for EVM-compatible chains and Rust/Soroban contracts for the Stellar network. Both suites expose the same logical interface through the SDK's adapter layer, so application code written against one chain works on the other with a config change. Every contract is MIT licensed, open source, and audited for production use. You deploy them yourself; Ankara Chain never holds custody of your keys or your assets.

## UUPS proxy pattern

Every ERC-20 token deployed through `TokenFactory` is an **ERC-1967 proxy**. The proxy stores your token's state (balances, metadata, status) and delegates all logic calls to one of the six template implementation contracts. This means:

- **You can upgrade** a deployed token by calling `upgradeToAndCall` on the proxy — only the deployer (admin) can do this.
- **Templates are shared** across all tokens of the same type. If a bug is found in `FarmlandToken`, a new implementation is deployed once and you point your proxy to it.
- **The proxy address is permanent** — your token's on-chain address never changes after deployment, even after an upgrade.

```solidity
// Under the hood — what TokenFactory does when you call deployFarmland():
ERC1967Proxy proxy = new ERC1967Proxy(
    farmlandImplementation,
    abi.encodeCall(FarmlandToken.initialize, (name, symbol, assetId, ...))
);
```

The SDK's `TokenFactory` class handles all of this for you via `deployFarmland()`, `deployCommodity()`, etc.

<Note>
  The UUPS implementation uses OpenZeppelin Contracts v5. The upgrade authority is the `admin` address set at deployment time — by default, the deployer's wallet. Store this key securely; losing it means you lose upgrade control over your tokens.
</Note>

## Roles and access control

Every deployed token carries a small permission model:

| Role | Who holds it | What it controls |
|---|---|---|
| **Owner / Admin** | Your deployer wallet (or an address you specify via `admin`) | `mint`, `burn`, `setStatus`, `pause/unpause`, `setIdentityVerifier`, all metadata-update functions, and UUPS upgrades |
| **Arbiter** | Optional — any address you pass to `DeployEscrowOptions.arbiter` | Dispute resolution in `MilestoneEscrow` — can release funds to payee or refund to payer |
| **Identity Verifier** | Optional — a deployed `WhitelistVerifier` (or any `IIdentityVerifier` implementation) | Gates who can receive tokens; set per-token via `setIdentityVerifier` |

There is no Ankara Chain platform key with any privilege over your contracts. Once deployed, the contracts are fully under your admin key's control.
