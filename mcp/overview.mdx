The Model Context Protocol (MCP) is an open standard that lets AI assistants like Claude call external tools in a structured, type-safe way. The `@ankarachain/mcp` package implements an MCP server that exposes the entire Ankara Chain SDK — token deployment, escrow management, fiat ramp flows, and on-chain queries — as a set of callable tools. Once connected, you describe what you want in plain language and Claude handles the transaction construction, signing, and submission for you.

## Installation

<CodeGroup>

```bash Global install
npm install -g @ankarachain/mcp
ankara-mcp
```

```bash Without installing
npx ankara-mcp
```

</CodeGroup>

## Connecting to Claude Desktop

Add the following block to your `claude_desktop_config.json` file (usually found at `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS, or `%APPDATA%\Claude\claude_desktop_config.json` on Windows):

```json
{
  "mcpServers": {
    "ankara-chain": {
      "command": "npx",
      "args": ["ankara-mcp"]
    }
  }
}
```

Restart Claude Desktop after saving. You will see **ankara-chain** listed under active MCP servers in the Claude interface.

<Warning>
**Keep your `claude_desktop_config.json` private.** If you pass `privateKey` directly in tool calls (see below), those values appear in Claude's context window and in your conversation history. Use a dedicated deployer wallet with only the funds needed for gas — never a wallet that holds significant assets.
</Warning>

## Available Tools

The MCP server exposes 24 tools, organised below by function. Tools that submit on-chain transactions require `rpcUrl` and `privateKey` fields. Read-only chain queries require only `rpcUrl`. Ramp provider tools (`get_ramp_quote`, `initiate_onramp`) interact with the off-chain ramp provider only and require neither field.

### Token Deployment

#### `deploy_token`

Deploys an ERC-20 RWA token through your `TokenFactory` contract.

| Field | Type | Required | Description |
|---|---|---|---|
| `template` | `string` | ✅ | One of: `farmland`, `commodity`, `real-estate`, `invoice`, `carbon-credit`, `mining-rights` |
| `name` | `string` | ✅ | Token name |
| `symbol` | `string` | ✅ | Token symbol, 3–5 characters |
| `assetId` | `string` | ✅ | Unique asset identifier string |
| `countryCode` | `string` | ✅ | ISO 3166-1 alpha-2, e.g. `"NG"` |
| `factoryAddress` | `string` | ✅ | Your deployed `TokenFactory` contract address |
| `rpcUrl` | `string` | ✅ | JSON-RPC endpoint |
| `privateKey` | `string` | ✅ | Deployer private key (0x-prefixed) |

**Returns**: `{ contractAddress, txHash }`

<Note>
For full metadata prompts (area, soil type, valuation, etc.), use the interactive `ankara deploy` CLI command. The MCP `deploy_token` tool deploys with minimal placeholder metadata — update it on-chain afterwards.
</Note>

### Token Operations

#### `mint_tokens`

Mints ERC-20 RWA tokens to a recipient address.

| Field | Type | Required | Description |
|---|---|---|---|
| `contractAddress` | `string` | ✅ | Token contract to mint on |
| `to` | `string` | ✅ | Recipient wallet address |
| `amount` | `string` | ✅ | Amount in whole units, e.g. `"100"` |
| `rpcUrl` | `string` | ✅ | JSON-RPC endpoint |
| `privateKey` | `string` | ✅ | Deployer private key |

**Returns**: `{ txHash, to, amount }`

---

#### `get_token_status`

Reads the name, symbol, total supply, and lifecycle status of an Ankara Chain token. **Read-only.**

| Field | Type | Required | Description |
|---|---|---|---|
| `contractAddress` | `string` | ✅ | Token contract address |
| `rpcUrl` | `string` | ✅ | JSON-RPC endpoint |

**Returns**: `{ name, symbol, totalSupply, status, statusLabel }` where `statusLabel` is one of `DRAFT`, `ACTIVE`, `SUSPENDED`, `REDEEMED`, `EXPIRED`.

---

#### `set_asset_status`

| Field | Type | Required | Description |
|---|---|---|---|
| `contractAddress` | `string` | ✅ | Token contract address |

| `rpcUrl` | `string` | ✅ | JSON-RPC endpoint |
| `privateKey` | `string` | ✅ | Admin private key |

**Returns**: `{ txHash, newStatus }`

### Escrow

Deploys a `MilestoneEscrow` contract for tranche-based diaspora payments.

| Field | Type | Required | Description |
|---|---|---|---|
| `payer` | `string` | ✅ | Address that funds the escrow |
| `payee` | `string` | ✅ | Address that receives released funds |

| `milestones` | `string[]` | ✅ | Ordered list of milestone amounts in whole token units, e.g. `["100", "200", "150"]` |

## Example: Deploying a Token with Claude

With the MCP server connected, you can issue plain-language instructions in Claude and it will call the appropriate tools on your behalf.

**You say to Claude:**

> "Deploy a farmland RWA token called 'Volta Basin Farmland' with the symbol VBF on Polygon Amoy. Use asset ID FARMLAND-GH-001 and country code GH. The factory is at 0xA1b2C3..., the RPC is https://rpc-amoy.polygon.technology, and my private key is 0xMyDeployerKey."

**Claude calls `deploy_token` and responds:**

```json
{
  "contractAddress": "0xDeployedTokenAddress...",
  "txHash": "0xTransactionHash..."
}
```

**You then say:**

> "Mint 10,000 VBF tokens to 0xRecipientAddress on the contract you just deployed."

**Claude calls `mint_tokens` using the address from the previous response.**

You can chain entire workflows — deploy an escrow, fund it, mark milestones delivered, and approve releases — all in a single conversation without leaving your IDE or touching the CLI.

<Warning>
Every tool call that requires `privateKey` sends that key through Claude's tool-use protocol. **Never use a wallet that holds significant funds.** Create a dedicated deployer wallet, fund it with just enough gas, and rotate it regularly. The private key you provide is used only for that specific tool call — it is not stored by the MCP server — but it does appear in Claude's context window for the duration of the conversation.
</Warning>
